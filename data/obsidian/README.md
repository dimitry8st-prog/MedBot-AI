## 🚀 Быстрый старт

### 1. Открытие vault

1. Скачать и установить [Obsidian](https://obsidian.md)
2. Открыть как vault: `File` → `Open folder as vault` → выбрать `data/obsidian/`
3. Установить community plugins (рекомендуется):
   - **Dataview** — для дашборда и запросов
   - **Templater** — для создания новых документов по шаблону
   - **Obsidian Git** — для версионирования

### 2. Навигация

**Основные точки входа:**
- [[Dashboard]] — мониторинг актуальности и статистика
- [[Источники]] — откуда берутся данные
- `Ctrl+O` (Cmd+O на Mac) — быстрый поиск документов
- `Ctrl+Shift+F` — полнотекстовый поиск

**Graph View** (`Ctrl+G`):
- Визуализация связей между документами
- Цвет узлов: по специальностям
- Размер узлов: количество связей

### 3. Создание нового протокола

1. Открыть template: `.obsidian/templates/Клинические рекомендации.md`
2. Скопировать содержимое
3. Создать новый файл в `01-Протоколы/{Специальность}/`
4. Заполнить frontmatter (метаданные) и разделы
5. Добавить wikilinks на связанные документы: `[[Название документа]]`
6. Сохранить

## 📋 Соглашения по оформлению

### Frontmatter (обязательные поля)

Каждый протокол должен содержать frontmatter с метаданными:

```yaml
---
title: "Полное название"
specialty: "специальность"
source: "Минздрав РФ"
source_type: clinical_recommendations
publication_year: 2024
evidence_level: "A"
status: active
created: 2026-07-28
updated: 2026-07-28
tags: [протокол, специальность, ключевые-слова]
aliases: [сокращения, синонимы]
---
```

**Значения полей:**

- `specialty`: кардиология | неврология | хирургия | терапия | эндокринология | и т.д.
- `source_type`: clinical_recommendations | protocols | drug_reference | textbook
- `evidence_level`: A | B | C | D | E (по методологии доказательной медицины)
- `status`: active | archived | draft

### Wikilinks

**Создание ссылок на другие документы:**

```markdown
[[Название документа]]                    # простая ссылка
[[Название документа|Текст ссылки]]       # ссылка с альтернативным текстом
[[Препарат#Дозировка]]                    # ссылка на конкретный раздел
```

**Правила использования:**

- Всегда создавать ссылки на связанные заболевания, симптомы, препараты
- Минимум 5-10 wikilinks в каждом протоколе
- Проверять, что ссылка ведёт на существующий документ (не красная)

### Теги

**Структура тегов:**

```
#протокол
#специальность (кардиология, неврология, и т.д.)
#ключевые-слова (гипертония, инсульт, диабет, и т.д.)
```

**Не использовать:**
- Пробелы в тегах (заменять дефисами: `#сахарный-диабет`)
- Слишком общие теги (`#медицина`, `#болезнь`)

### Уровни доказательности

| Уровень | Описание |
|---------|----------|
| **A** | Систематические обзоры, мета-анализы, РКИ |
| **B** | Хорошо спланированные контролируемые исследования |
| **C** | Наблюдательные исследования, когортные исследования |
| **D** | Описания случаев, мнения экспертов |
| **E** | Консенсус экспертов, клинический опыт |

## 🔄 Workflow обновления данных

### Периодичность проверки

- **Ежеквартально:** Проверка обновлений на официальных источниках
- **Раз в полгода:** Ревизия протоколов старше 2 лет
- **По запросу:** Добавление специфических документов

### Процесс добавления нового документа

1. **Поиск и загрузка**
   - Проверить официальный источник (cr.minzdrav.gov.ru, scardio.ru и др.)
   - Скачать PDF или получить HTML

2. **Валидация**
   - Проверить год публикации (приоритет <2 лет)
   - Проверить статус утверждения
   - Проверить уровень доказательности

3. **Конвертация**
   - PDF → Markdown (вручную или с помощью скрипта)
   - Структурирование по template
   - Добавление frontmatter

4. **Обогащение**
   - Добавление wikilinks на связанные документы
   - Создание карточек для новых симптомов/препаратов
   - Добавление в граф знаний

5. **Индексация в RAG**
   - Запуск `python backend/scripts/reindex_obsidian_vault.py`
   - Проверка в ChromaDB
   - Тестирование поиска через MedBot API

6. **Документация**
   - Обновление [[История обновлений]]
   - Обновление [[Dashboard]]
   - Git commit: `feat: add протокол "{название}"`

### Архивация устаревших протоколов

1. Изменить `status: archived` в frontmatter
2. Переместить файл в `99-Архив/`
3. Обновить ссылки на новую версию (если есть)

## 🔗 Интеграция с MedBot AI

### RAG индексация

Этот vault является **источником данных** для RAG Engine MedBot AI.

**Workflow:**

```
Obsidian Vault (markdown файлы)
        ↓
ObsidianIngestion Pipeline (парсинг frontmatter + wikilinks)
        ↓
Text Chunking (800 токенов, overlap 100)
        ↓
Embedding Generation (multilingual-e5-large)
        ↓
ChromaDB (векторная индексация)
        ↓
MedBot API (RAG search)
        ↓
Пользователи (Web UI, Telegram Bot)
```

**Скрипты:**

```bash
# Полная переиндексация vault
python backend/scripts/reindex_obsidian_vault.py

# Индексация одного документа
python backend/scripts/ingest_obsidian_document.py --file "путь/к/файлу.md"

# Проверка индекса
python backend/scripts/check_chromadb.py
```

### Метаданные в ChromaDB

Из frontmatter автоматически извлекаются:

- `title` → document_title
- `specialty` → specialty
- `source` → source
- `source_type` → source_type
- `publication_year` → publication_year
- `evidence_level` → evidence_level
- `status` → status

Используются для фильтрации и reranking в RAG поиске.

## ❓ FAQ

**Q: Как добавить новый препарат?**  
A: Использовать template `.obsidian/templates/Препарат.md`, заполнить все разделы, добавить wikilinks на протоколы применения.

**Q: Что делать с устаревшим протоколом?**  
A: Изменить `status: archived` и переместить в `99-Архив/`. Если есть новая версия — добавить ссылку.

**Q: Как проверить актуальность всей базы?**  
A: Открыть [[Dashboard]] — там автоматически отображаются протоколы старше 2 лет.

**Q: Можно ли редактировать протоколы?**  
A: Да, но только для исправления ошибок или дополнений. Основное содержимое должно соответствовать официальному источнику.

**Q: Как создать связь между документами?**  
A: Использовать wikilinks: `[[Название документа]]`. При первом упоминании препарата/симптома — создать wikilink, затем создать карточку.
